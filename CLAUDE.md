# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout

Three separate Swift/Xcode units plus Python tooling:

- `Wordwell.xcodeproj` + `Wordwell/` — iOS app target (iOS 27). `App/` holds `AppContainer` (the only production composition root), `AppRouter` (selected tab + five independent typed nav paths), `DictionaryAILookupAdapter`. `Features/` holds screens/view models; features stay in the app target, not separate modules.
- `Packages/WordwellKit/` — local SwiftPM package, four libraries: `WordwellDomain` (Foundation-only models + repository/AI contracts), `WordwellDesign` (tokens, fonts, components, SVG rendering; must not import Domain/Data/AI), `WordwellData` (bundled SQLite dictionary + local repositories; depends on Domain), `WordwellAI` (depends on Domain). One test target: `WordwellArchitectureTests`.
- `Docs/` — despite the name, also a standalone SwiftPM package `WordwellAI` (`WordwellAICore`, `WordwellAIFoundationModels`, `wordwell-ai` CLI) alongside the spec docs. It is NOT yet what the app links; the app uses `WordwellKit/Sources/WordwellAI`. See `Docs/README.md` for the CLI and its anti-hallucination/exam-practice design.
- `Tools/` — Python asset/dictionary generators.

Read `ARCHITECTURE.md` (dependency direction, persistence decision, phase status) and `design.md` (authoritative visual spec; `Docs/02_DESIGN.md` just points to it) before structural or UI work. `Docs/01_ARCHITECTURE.md`, `03_AI_FEATURES.md`, `04_SVG_ASSET_SPEC.json` are product specs.

## Commands

```bash
# WordwellKit tests (run from Packages/WordwellKit)
swift test
swift test --filter WordwellArchitectureTests.<TestClass>/<testName>   # single test

# AI package tests + CLI (run from Docs/; CLI needs macOS 26+ with Apple Intelligence)
swift test
swift test --filter WordwellAICoreTests.<TestClass>/<testName>
swift run wordwell-ai availability
swift run wordwell-ai eval --min-pass-rate 0.85

# App
xcodebuild -project Wordwell.xcodeproj -scheme Wordwell -destination 'platform=iOS Simulator,name=<device>' build

# Tools (from repo root)
python3 Tools/validate_svg_assets.py            # also runs as an Xcode build phase; --phrasal for phrasal-verb set
python3 Tools/import_dictionary.py <english-wordnet-2025-json.zip> <out.sqlite>   # regenerates Dictionary.sqlite
```

No linter is configured.

## Architecture notes that span files

- Dictionary is a bundled, read-only SQLite (FTS5) built from Open English Wordnet by `Tools/import_dictionary.py`; source/attribution in `Docs/05_DICTIONARY_SOURCE.md`. User data (saved words, progress, settings) is separate local storage behind repositories. No cloud sync, no remote AI.
- ViewModels take only the contracts they need; never touch `AppContainer`, SQLite, or Foundation Models directly. Services/repositories never navigate.
- `LanguageAIService` is the provider-independent AI boundary. `NoAIService` / `UnavailableDictionaryRepository` are explicit fallbacks that report unavailability — they must never fabricate learning content.
- `WordEntry` carries no illustration asset name; `LocalIllustrationBindingRepository` resolves bindings from `illustration_bindings.json` (schema v2, monochrome line art). Missing binding must leave the screen usable. Existing `_plate` asset names are stable IDs despite now being unframed line art. SVGs are generated by `Tools/*plates*.py`, `word_line_art.py`, `action_scenes.py`, and `Tools/PhrasalVerbs/`.
- Colors: semantic tokens auto-switch light/dark. Secondary text uses `#736E64`, not `design.md`'s `#8C877C` (fails 4.5:1); tests enforce contrast.
- Docs AI package: bump `AIPrompts.version` on any prompt/schema change, then run `eval`. Exam practice must stay brand-neutral (`RestrictedTermsPolicy` stores only FNV-1a fingerprints; never add plain-text restricted terms to the repo).

## Design rules (from `design.md` — authoritative; re-read it for exact tokens)

Apply to any UI or illustration work:

- Style: warm editorial print-dictionary, cream paper, ink-monochrome. Fraunces for titles/headwords/card headlines only; Work Sans for everything else. No Inter/Roboto/system-Arial look.
- Color is functional only: CEFR badges (A=green, B=amber, C=blue), green dot for on-device AI cue, literal color-word swatches. No new accents without a stated function. No gradients, uniform drop-shadow cards (use 1px borders), or tracked-out ALL-CAPS eyebrows.
- Layout: 22–24pt side padding, 14–18pt card padding, radii 10–14 cards / 20–24 pills / 3–6 badges, tap targets ≥44pt. Screen header = Fraunces title + one-line muted subtitle + illustration top-right.
- Buttons: primary solid ink + cream text, pill; secondary 1px ink border. Never put `→` in button/link text; use a real chevron.
- Tab bar: native Liquid Glass, 5 tabs (Home · Grammar · Library · Practice · Profile), SF Symbols. Dictionary search opens from Home.
- Illustrations: thin dark rounded-outline line art, `fill="none"`, ~1.5–2pt visible stroke, tinted with semantic ink in Dark Mode. No plates, frames, captions, colored backgrounds, shading. Only fill exception: a word that names a color. viewBox 160×96 (phrasal verbs), 342×196 (dictionary). UI icons are SF Symbols, not SVG illustrations. Same icon = same meaning everywhere.
- Every AI entry point shows the privacy cue "On-device · Private & secure". Settings row label: "On-device AI (Apple Intelligence)" with "Runs entirely on this device — nothing leaves your phone."
- Accessibility: body text ≥4.5:1 (use `#736E64` for secondary text), level meaning never by color alone, real semantic controls.
- Full stats live only in Profile; stat boxes only in Practice and Profile.
